MinorUPI API Documentation

Complete reference, code examples, webhook security, and AI integration prompt.

1. Introduction & Quickstart ▼

MinorUPI is a self-hosted private UPI gateway. Customers scan a dynamic QR or tap Pay Now directly to your FamApp UPI ID with zero aggregator transaction fees. Automated IMAP verification polls Gmail, verifies newly arrived credit emails using strict UID baselines and UTC window checks, and fires HMAC-signed webhooks.

Quickstart Checklist

  • Connect your FamApp UPI ID, Gmail address, and 16-character Google App Password in the Connect menu.
  • Generate an API key in the API menu (shown once on creation).
  • Create an order from your server using POST /api/v1/orders and redirect the customer to payment_url.
  • Verify X-Signature in your webhook handler and fulfill the purchase only when status === "paid".
2. Authentication ▼

Authenticate all /api/v1/* requests from your backend server using either header (rate limit: 60 requests/minute per key):

Authorization: Bearer upi_live_your_secret_key_here
# Or:
X-API-Key: upi_live_your_secret_key_here

Never expose your API key inside frontend JavaScript or mobile app source bundles.

3. API Endpoints (Request & Response Examples) ▼

Create Order — POST /api/v1/orders

Default expiry is 5 minutes (overridable via expiry_minutes). Automatically allocates a unique paise offset (e.g. ₹50.00 -> ₹50.01) among pending orders and snapshots the current Gmail inbox baseline UID.

// Request
POST /api/v1/orders
Content-Type: application/json
Authorization: Bearer <YOUR_API_KEY>

{
  "amount": 50.00,
  "order_id": "ORD_1001",
  "expiry_minutes": 5,
  "callback_url": "https://yoursite.com/api/webhook",
  "redirect_url": "https://yoursite.com/order-complete",
  "note": "Pro Subscription"
}

// Response (201 Created)
{
  "success": true,
  "data": {
    "order_id": "ORD_1001",
    "base_amount": 50.0,
    "payable_amount": 50.0,
    "payment_url": "https://gateway.yoursite.com/pay/ORD_1001",
    "qr_base64": "data:image/png;base64,...",
    "upi_link": "upi://pay?pa=...",
    "expires_at": "2026-11-18T08:05:00+00:00",
    "status": "pending",
    "note": "Pro Subscription"
  }
}

4. Code Examples (cURL, Python, Node.js, PHP) ▼

cURL

curl -X POST https://YOUR_GATEWAY_URL/api/v1/orders \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"amount": 99.00, "callback_url": "https://yoursite.com/webhook"}'

Python (Requests)

import requests

resp = requests.post(
    "https://YOUR_GATEWAY_URL/api/v1/orders",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={"amount": 99.00, "callback_url": "https://yoursite.com/webhook"}
)
order = resp.json()["data"]
print("Pay at:", order["payment_url"])

Node.js (Fetch)

const res = await fetch("https://YOUR_GATEWAY_URL/api/v1/orders", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer YOUR_API_KEY"
  },
  body: JSON.stringify({ amount: 99.00, callback_url: "https://yoursite.com/webhook" })
});
const { data } = await res.json();
console.log("Pay at:", data.payment_url);

PHP (cURL)

$ch = curl_init("https://YOUR_GATEWAY_URL/api/v1/orders");
curl_setopt($ch, CURLOPT_HTTPHEADER, [
    "Content-Type: application/json",
    "Authorization: Bearer YOUR_API_KEY"
]);
curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode([
    "amount" => 99.00,
    "callback_url" => "https://yoursite.com/webhook.php"
]));
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
$result = json_decode(curl_exec($ch), true);
$paymentUrl = $result["data"]["payment_url"];
5. Webhooks & HMAC-SHA256 Verification ▼

When an order becomes paid, expired, or cancelled, MinorUPI sends a POST request to your callback_url with header X-Signature (HMAC-SHA256 hex digest of raw JSON body). Retries run with backoff delays (0s, 2s, 6s) until HTTP 2xx is returned.

# Python HMAC Verification
import hmac, hashlib

def verify_signature(raw_body_bytes, header_sig, webhook_secret):
    expected = hmac.new(webhook_secret.encode("utf-8"), raw_body_bytes, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header_sig or "")
6. Status Lifecycle, Expiry & Anti-Replay Rules ▼
  • Statuses: pending → paid | expired | cancelled | failed.
  • Expiry: API orders default to 5 minutes; Payment Links use your selected minutes. expires_at is fixed in UTC and never extended by refreshing.
  • Strict Email Verification: Only brand-new emails with UID > order.baseline_uid, UTC timestamps inside [created_at - 30s, expires_at], exact payable amount, allowed sender domain, and an unused UTR can mark a pending order paid.
  • Late Arrivals: Emails arriving after expires_at never revive an expired order and are logged under Transactions → Unmatched credits. Paid orders never expire.
7. Frequently Asked Questions ▼

What happens if two customers buy the same ₹10 item at once?
MinorUPI allocates distinct payable amounts (₹10.00 and ₹10.01) while both orders are pending so emails never collide.

What if a customer's phone clock is wrong?
The checkout countdown calculates remaining seconds from the gateway's UTC server_now and expires_at.

Can clicking Pay Now or polling mark an order paid?
No. Only verified IMAP email arrival marks an order paid.
